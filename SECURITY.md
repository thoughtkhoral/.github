# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private
security reporting feature for the affected repository when it is enabled. If
private reporting is unavailable, contact an organization owner through the
ThoughtKhoral GitHub organization before disclosing details publicly.

Include the affected repository and version, impact, reproduction steps, and a
safe contact path. Do not include access tokens, passwords, private room data,
or production credentials in an issue or pull request.

## Supported versions

There is currently no production-supported release. The active MVP branch and
published contract releases receive best-effort security review while the
project is in development. Deployment-specific security remains the operator's
responsibility.
